# 密集W8A8：组件准备，不修改当前评测模型

此前软件8位权重在BF16 dot前解码，组件慢35%–52%；这次使用已通过能力检查的真正INT8×INT8→INT32 dot。每输出行固定权重scale，激活每步按token做absmax/RNE量化，再由整数GEMM融合scale并写BF16。计时必须包括激活量化，静态权重打包成本另记；不能把只测整数dot当完整组件速度。

计划原MiniCPM5-2B第0层QKV/O/GateUp/Down以及真实lm_head权重，合成M64激活，附M17/N130/K259非整tile边界。现用flag_gems.mm BF16为控制，四个warp/tile系列候选逐一保留。按相同Graph改变激活、量化权重和scale；GPU完整INT32及FP32参考、CPU精确整数抽点、完整输出/guard/输入/RNG检查。完整张量和派生权重只留容器，GitHub不上传模型或权重副本。

这是有数值变化的近似计算，正确性参照必须是量化数据的真实矩阵积；与原BF16模型的偏差另外记录，不能据此宣称Math。只有足够组件收益才考虑实际模型与新Math严格>95%。如后续保留BF16权重用于prefill再缓存INT8权重，额外GPU存储必须在正式KV内存分析前计算在内，不能隐藏容量代价。

当前只有CPU舍入/INT32范围检查，没有GPU速度或质量结果；正在运行的282份正式候选源、Math/完整4K流程不改动。
