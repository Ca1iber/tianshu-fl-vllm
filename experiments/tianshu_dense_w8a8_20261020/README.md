# 真正的 W8A8 密集 GEMM 实验

本实验使用 INT8×INT8→INT32 的 tl.dot，每个 token 动态 absmax/RNE 量化激活，权重按输出通道静态量化，GEMM 内融合缩放并输出 BF16。与之前把软件压缩权重解码为 BF16 的方案不同，这里实际执行整数乘法；尚未接入模型。

CPU 原型检查通过：3054 个舍入示例、254 个正负半整数 tie，最坏 K6144 的 INT32 累加无溢出。GPU 驱动会在当前完整 4K 和成对 K 分段扫描结束、GPU 确认空闲后串行执行。

GPU 计划使用真实 checkpoint 的 layer0 qkv/o/gateup/down 和独立 lm_head 权重，分别测 M1/M8/M64，另加 M17/N130/K259 的非整除与 A 行步长场景，共 16 个场景、8 个 tile/warp/stage 配置。控制为实际 flag_gems.mm(A_BF16,W_BF16.T)。每次候选 Graph 回放都包含动态激活量化及完整整数 GEMM；只排除记录在案的一次性权重打包。每配置交替七组控制/候选计时，每组20次回放。

每个配置还在同一张 Graph 下变更输入、权重符号、权重缩放并验证三个阶段。GPU 检查整个 INT32 结果：只有实际绝对乘积总和严格小于2^24时才使用 FP32 整数参考，另用独立 CPU INT64 检查所选输出。完整激活量化与 CPU 一致，量化后 BF16 输出使用完整参考；与原始 BF16 的近似误差单独记录。零行、半整数、尾部、越界保护、输入不变和 RNG 不变均检查。

verify_gpu.py 在 CPU 独立重新计算完整激活量化、原始权重选定行、选定输出整数和缩放结果及计时统计。它不声称离线重新计算全部 GPU 输出。完整 GPU 断言、源码快照和用于独立抽样复核的 PT 数据保留在容器；GitHub 只保留代码、报告和关键统计。

原始目录：/workspace/benchmark-results/20261020_dense_w8a8_GPU_tianshu。

当前仅完成 CPU 准备，不能声称 GPU 通过、模型正确率通过或服务收益。如果保留 BF16 权重给 Prefill，新增加的 INT8 权重/scale 会挤占 KV 空间，后续接入前必须计算此代价。本实验不会修改 checkpoint 文件、正在运行的服务或正式最佳配置。
