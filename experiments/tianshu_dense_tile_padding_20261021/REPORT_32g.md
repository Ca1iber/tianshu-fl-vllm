# GEMM补齐32/64整tile：26组件场景、78变数据相位通过

原始b9整数GEMM不改；A量化时在同一个被计时的GPU kernel中将M<=32补到32、33..64补到64，额外行写q=0与EPS/127 scale。实际M32/64直接沿用原量化器。不是在计时外填零。

全部26场景含GateUp与LM、M1/3/7/8/17/32/37/40/48/56/63/64及strided M37。每个3次真实变数据Graph相位：全部有效INT32和BF16输出逐位相同、CPU独立重新量化A和选中W、INT64点积、保护区/输入/RNG全部通过；padding行INT/输出0与scale精确值也通过。78组完整设备校验与78组CPU独立点积重检通过。

|---|---:|---:|---|
|GateUp8->32|0.092763|0.059928|真实量化+补齐写入+GEMM|
|GateUp40->64|0.132828|0.067487|同上|

|LM40->64|1.889850|0.610973|同上|

7组轮换顺序、每组20 Graph重放取median。所有指针采用明确256B对齐及256元素保护区；不推广到此前已证实原GEMM可能错误的16元素偏移情形。

对比特意固定同一个tile配置以隔离padding效应。LM37..63原直接使用BN128，本轮不是此前所有配置扫描的最好直接值（此前BN256约1.33ms），不能把同配置约3.1倍当作对所有最佳直接实现的提升。本轮也没有BF16对照或完整服务/Math；仅证明同数学输出的INT8补齐组件显著快于相同配置的masked M。

现有5482.79合格版本尚未接入补齐，LM小批次仍保留BF16。下一步先接GateUp，核实真实Graph调用、额外buffer内存与小测收益，新的质量/正式成绩再另行报告。
