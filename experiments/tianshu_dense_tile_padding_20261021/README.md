# 真INT8整tile补齐：计入实际量化/补齐成本的独立组件

直接实际M与补齐M采用相同的目标tile：M<=32用BM32/BN128/w2，33..64用合格的BM64（GUP BN256，LM BN128）/w4。候选在实际GPU量化器中将真实M之外的行写为q=0和合法scale，再调用未修改的b9整数GEMM。量化kernel REAL_M运行期参数避免每个M重新编译；M本来等于32/64时完全沿用原量化器，不增加不必要的工作。没有在计时外预填补齐输入。静态W打包单列排除。

实际层0GateUp和LM，M1/3/7/8/17/32/37/40/48/56/63/64，加M37行stride2055共26案例。每案例三次改变输入/权重/scale；含0行、RNE半整数，完整设备有效行INT32/BF16位级比较及独立设备整数参考，补齐行q/int/out必须0，scale合法，输入/RNG/前后哨兵保持。CPU重算全部A和选中W量化/INT64。7轮交替×20热Graph计时包括完整A量化、补齐行写入与GEMM。

参考与候选中间buffer均用256元素前哨，并在运行时确认指针对256字节对齐。此前16元素前哨下旧静态M64错误保留在runtime_m目录，不能用新fixture静默抹掉。对齐是本实验显式契约，不声称已隔离最小对齐要求。

记录实际编译缓存键与设备二进制SHA，要求每角色/target只用一个GEMM二进制；需要补齐的M共用一个quantize二进制/stride。尚无GPU结果时CPU gate仅证明计算体与mask/source安全界，不计收益。排在当前LM precision新质量/条件正式4K之后，不并发GPU。不是模型/正式成绩，未自动采用。
