# BF16存储/FP16内部dot：真实权重GEMM组件探索

不是已采用优化。用MiniCPM5-2B第0层实际Q/K/V拼接、O、gate/up拼接、down矩阵，输入激活为合成BF16。比较4路径：实际FlagGems BF16基线；自有同配置BF16 dot；保留BF16权重与激活、在寄存器转FP16 dot；预转换静态FP16权重、激活仍BF16并在寄存器转FP16。所有自有输出保持BF16、累加FP32，未修改checkpoint、官方启动参数或KV精度。

M64三套固定tile/splitK，M2048一套已有最佳prefill配置，共16组×4模式；每组两阶段原位改变激活和两种GPU权重存储，再重放同一Graph。全输出对FP32参考、CPU8×32采样参考检查，容差与此前GEMM试验相同atol=.02/rtol=.01，另记录与原FlagGems逐位一致性，不把近似说成逐位。CPU样本值会序列化供离线重算，全部GPU矩阵不序列化。

计时7轮交错顺序、每次20个Graph重放。预转换静态权重的单次转换成本与额外存储不在GEMM事件时间里，明确记录，不能据局部结果宣称端到端收益或质量。先比较同配置BF16/FP16 dot，再看是否真正超过当前FlagGems或M2048最优BF16；若有潜力才进行完整路由、实际模型质量和服务验证。CPU门槛只验证16组tile网格及splitK覆盖，不宣称GPU通过。
