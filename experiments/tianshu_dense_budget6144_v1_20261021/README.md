# 6144默认调度预算候选

8192完整4K前两次计入轮次显示吞吐约5500、TTFT高于已通过的4096预算版本，因此准备中间6144预算的小规模服务对照。没有更改原8192运行源。

复用已通过Math101/105的359源配置，两臂保持GateUp整数、小批次LM BF16、LM64整数、预填充linear、gpu4加载和原始serve命令。仅在受限型号与原默认参数条件满足时，把外层默认预算从4096改为6144；显式参数保持。long guard同步要求实际6144，并保持独立的8192短上下文阈值、8192 arena容量以及12288-byte K8V16页。

预热配置仍采用原99点上限，按6144预算裁剪后预计实际91点，审计必须同时检查实际最大M6144；这一预计值会在GPU启动后验证。CPU检查执行实际EngineArgs方法AST、原嵌套默认包装、明确参数保留、异常传递、隔离配置与hook边界。CPU gate不代表GPU通过或收益。

每臂4K/1K、C64/N64三轮，剔除首轮，原始usage逐请求核验。先看同源对照与既有同客户端参照；值得继续时才跑新Math与N256完整4K。此候选当前未启动GPU，未采用。
