# 原生 W4A16 / AWQ Down64，42 层轮换组件测试

父版本：r3 9044c25（正式 4K 5950.75 total tok/s）。本实验不改变服务、原始 checkpoint、模型架构或已合格配置；不运行完整模型或正式 benchmark。

使用42层真实 Down BF16 [2048,6144] 权重。每128个 K 为一组，scale=BF16(max(abs(W))/7)，零组用正的最小保护值；量化为 clamp(round(W/实际 BF16 scale),-8,7)+8，zero=8。这是 RTN 量化并采用 AWQ 的物理格式，未经激活感知校准，不称为校准后的 AWQ 模型。采用已通过非恒定完整 GPU 测试的 N 顺序 [0,2,4,6,1,3,5,7]，qweight int32 [6144,256]，scale BF16 [48,2048]，qzero int32 [48,256]。

输入来自旧组件的三个完整 H64 fixture（由真实 GateUp 权重产生，不是在线请求 trace），按层循环移位。CPU 检查所有42层完整打包逆变换；对第0、20、41层的3种输入分别计算全 K、全64x2048的原始 BF16 和 BF16反量化权重 FP64 参考。全部数值阈值在第一次 GPU 前固定：每格误差 <= .012*abs(ref)+.006*RMS(ref)，相对L2 <= .006，全部有限。量化模型相对原始模型的误差另列，不等同于 kernel 错误，仍需未来独立 Math500。

对照使用同一 r3 的全部环境开关和 sitecustomize 栈，直接调用实际 _iluvatar.ops.mm.mm，检查原始模块与有效 _launch_mm 的来源。M64 不经过 M2048 的 prefill override。候选调用实际 aten._weight_int4pack_mm_awq。禁止仅以 torch.mm 未确认的调度作为对照。记录实际加载库、源码和输入 SHA。

GPU 对全部42层、全部3个 phase 保存完整输出；检查 eager / CUDA Graph replay 在输出 NaN poison 后完全一致，输入/权重/scale/zero 的版本与全字节 SHA、RNG 不变。每个图包含42个不同真实权重 bank，避免同一6MB权重重复测试的缓存偏差；输入在层间也独立分配。计时7轮，每轮10次全42层，交替对照/候选顺序，第一轮排除；分别测 eager 和 graph。单 bank 热缓存速度不作为主结论。组件中不生成激活量化及 INT32 全矩阵中间结果。

任意数值/输入/环境检查失败则不采用；原生库异常不通过重跑寻找好结果。组件只有通过正确性且图计时有显著收益才考虑集成，并须重新通过 C8、C64 >95% 后才能短4K；不直接声称整机吞吐提升。最晚23:58北京时间退出，单次 GPU 程序900秒超时。所有源码和控制器在首次GPU前提交冻结；原始大数组只在容器保存，GitHub存代码、关键结果、SHA和报告。
