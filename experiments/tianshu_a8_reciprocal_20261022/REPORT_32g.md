# A8 除法改倒数：可修正为一致，当前实现反而变慢

当前A8逐行采用 FP32 RN `scale=max(abs(A),1e-8)/127`，逐元素除scale并RNE取整。直接改为乘FP32倒数并不等价：在有限BF16域构造的81084416个枚举元素（包括重复零/填充）中，发现7424个量化整数差异，集中在半整数边界。不能不经验证直接替换。

两种修正：half_div仅对绝对值等于row_peak/2的元素使用原标量除法结果；half_fma用 `fma(-63.5,scale,row_peak/2)` 与舍入边界比较。低于epsilon和非有限peak保留旧vector-div分支。声明的等价性范围是有限BF16输入；未宣称任意NaN/Inf语义都已覆盖。

CPU先枚举19796个peak，覆盖相对指数差0..9的有效BF16值和双符号，更小相对值有<0.247079的量化零上界。另覆盖全部25688个clamp内有限BF16 words。GPU每种实现实际执行19803行×4096=81113088元素，保存全q/scale，由独立CPU重算；两种修正与旧实现均逐位相同。6种性能shape、3次输入变化、strided/tail、guards/RNG和GPU/CPU交叉审核全部通过。81M是构造域元素数，不能称为81M个唯一输入组合。
