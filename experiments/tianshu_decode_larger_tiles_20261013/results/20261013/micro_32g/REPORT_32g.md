# 天数 BI-V150 32g：L0 Decode KV64/128数值通过但4K更慢

在已验证无sink L0初始化、producer/reducer TILE一致的基础上，微测TILE64/w4、w8、w16和TILE128/w8、w16，均stage1；同轮保留TILE16/w4/stage1及当前最好TILE32/w4/stage1参照。原kernel浮点body、网格、64位整数/物理指针保留，L0生成源仍4a1f8bdfdb5b9399702941a0e499e62b52f104737aba6012a9056ef36f5c4d4e。

结论：4K/5K目标下大tile更慢，B64/4K中KV64/w4约增加25.7%时间，KV128/w16约增加110.5%。只在B2/32768边界单算子中KV64/w8约快5.7%，不支持当前4K服务采用。没有运行新的服务A/B、独立Math或正式benchmark，当前正式最好3426.62/Math103保持。长context仅是单算子正确性/微测边界，不是16K服务benchmark。

不能把旧KV32失败归因为所有更大tile算法不正确；L0与一致的两阶段契约后本次数值全部通过，但4K性能无收益。未采集硬件性能剖析，TODO，不能凭耗时猜测寄存器或带宽根因。
