# 投机验证阶段的 native GQA tile扫描

固定同一无sink L0修正，仅改变2D tile和launch配置。5个配置为M16/KV32/w4/s3（原配置）、M64/KV32/w4/s2、M64/KV64/w4/s2、M64/KV128/w8/s2、M128/KV64/w8/s2。7个场景覆盖Q8/K21、Q8/K23、Q8/K4096、双请求短KV、混合Q1/Q8、B8和B64的Q8/K4096，实际交错KV/随机分页和非连续query，35/35数值检查及输出尾部保持，FP32参考另以CPU独立抽查验证。

B64验证8 token时，各配置中位耗时依次6.134235/3.074794/5.499004/6.657229/2.326513ms。M128/KV64相比原配置算子耗时−62.0733%，M64/KV32约−49.875%。不同tile独立调用实际forward并交替与相同FA2参考计时，保留所有原始计时样本；这不是服务吞吐或官方benchmark，不从算子百分比推导端到端提升。

进程候选只对非3D且平均query数不超过8的验证批次使用M128/KV64；长Prefill保持原tile，3D decode保持原kernel。实际服务收益、独立数学与正式成绩待验证，当前最佳标签保持不变。
