# 天数32g：下一步框架候选的源码核对

复核了Decode分段scratch布局。虽然框架按最多64个segment分配缓冲区，原native源bab2c0b9...的producer和reducer都用实际NUM_SEGMENTS_PER_SEQ计算线性地址（包括token/head/segment步长），不是按Tensor形状64寻址。因此实际S8的有效写入/读取本来就是紧凑的；仅将torch Tensor view改为S8不会自动节省8倍scratch访存，本次不为这个错误假设启动GPU实验。此结论只涉及地址布局，不等于整个框架不可能进一步优化scratch分配或生存期。
