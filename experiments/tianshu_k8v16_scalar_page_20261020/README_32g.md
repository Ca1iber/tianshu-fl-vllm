# K8V16页表标量读取：CPU准备

当3D decode的TILE_SIZE与16-token物理页相等时，同一tile的16个token读取同一个页表项。候选将向量形式的页表读取明确改为一次标量读取再广播；其余tile/2D路径保留原实现，64位页号/偏移和全部浮点运算不变。

CPU证明131072个j/lane组合地址相同，生成源可精确逆变换，只有kernel_unified_attention函数AST改变。尚未GPU编译或计时；编译器也可能本来就已消除重复，所以不能预言收益。

准备10场景、两种相同物理布局，复用已通过的独立GPU FP32/CPU参考、同一Graph变数据、完整writer存储、输出/scratch哨兵与RNG门槛；所有候选输出额外要求与原实现逐位相同。等正式16K和已排队组件结束再启动，不与当前GPU任务并发。

首次GPU入口在数值和计时之前被源哈希检查拒绝：探针误把原始cache reader直接传给要求已生成K8 reader的变换。失败日志及旧探针/CPU清单留原raw目录。已修正为两组都先生成并验证K8 reader，再对候选进行标量变换；kernel变换本身和131072项地址证明不变。新运行使用独立v2目录，不覆盖失败原件。
