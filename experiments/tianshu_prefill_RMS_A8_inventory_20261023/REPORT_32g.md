# prefill的RMS+A8融合接入调查：真实图限制，尚无GPU候选

对新组合首次完整C64产生的原始FX图进行AST扫描，不导入Torch或使用GPU。当前实际编译范围恰为43份[1,4096]通用图和43份[64,64]静态图，没有静态4096图；前43份在当前RMS钩子前后字节完全相同。通用图内共42处QKV前norm、42处GateUp前norm，norm输出均只交给相应projection；QKV首层无残差、其余41层有，GateUp全42层有残差，IR norm节点保留。

不能将M64的融合直接复制到整个[1,4096]图而无条件量化：通用图仍承担未量化的M区间。当前QKV只有128/512/4096走native INT8，而64保留BF16。若进一步试prefill融合，可以新建额外的compile_sizes=4096静态点，再只在[4096,4096]改写，保持通用图和M64现有路径；本机vllm/config/compilation.py的compile_sizes、compile_ranges_endpoints注释明确说明静态单点范围优先于相交通用范围。源及SHA记入CPU_INVENTORY_GATE，本次未更改实际配置。

后续仍需先扩展真实权重、残差/非残差、M4096的norm+A8组件数值和真实Graph返回对象验证，并量化完整norm+quant+原GEMM链延迟；已有M64组件25.69%不当成M4096收益。若组件有收益，另建模型版本与来源/配置/42层实际命中/二进制审计，明确扩展compile_sizes并核对各旧组件“unchanged”声明的作用范围，不能把旧[64]记录当成整体仍未改的证明。新模型须重新完成C8/C64各105题严格>95%，再同期短4K及条件正式4K。
