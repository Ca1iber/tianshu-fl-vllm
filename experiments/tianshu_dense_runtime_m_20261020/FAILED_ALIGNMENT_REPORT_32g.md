# 运行期M sweep失败：旧静态基准对偏移指针的隐含约束

原26案例sweep保持失败状态：只完成11个GateUp案例，M64第一阶段的两版本全矩阵比较断言失败，LM与行stride案例未执行。不能声称26案例已过，也没有推广新内核。

独立M64诊断复用了相同输入与实际层0权重，对缓冲区分别用0、16、256个元素的前哨偏移。0与256前缀时，各指针对256字节对齐，两版本完整整数和BF16逐位一致，并通过完整设备整数参考。16前缀时q/s/out/integer分别偏移16/64/32/64字节，旧静态基准出现784722个整数错误；新运行期M版本完整整数参考仍正确。32个保存错点已从原始BF16行独立CPU重新量化并用INT64点积复算，全部确认旧静态值错误、新动态值正确。全部前后边界保持。

因此原断言失败不能归结为动态M算术错误。该诊断同时改变多个指针对齐，尚未隔离具体指针及最小对齐要求。现有服务使用独立torch.empty分配的中间结果；诊断未修改服务内核或合格版本。

实际编译元数据还显示：M64无整数输出计时版本静态132寄存器、动态224，说明不能只追求减少二进制数量而忽略热路径代价。后续可在独立组件中复查实际分配方式，并测试将M37/40等补齐到32/64整块；尚未测量，不计收益。所有源与失败数据保留。
