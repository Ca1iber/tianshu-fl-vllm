# Down 激活分块缩放 CPU 数值结果

42 层、504 个已有合成工件全部完成。保持原有逐输出通道 W8 权重打包，只把激活的逐行缩放从 K6144 改为更小的 K 分组。K128 的相关验证相对 L2 误差为 1.7794%，原 K6144 为 3.4638%，相对降低约 48.63%；K512 为 2.2106%。尚无 GPU 速度或模型正确率结论。

| 激活 K 分组 | 每行缩放数 | phase0 相对 L2 | phase1/2 相关验证相对 L2 |
| --- | ---: | ---: | ---: |
| 128 | 48 | 1.8492% | 1.7794% |
| 512 | 12 | 2.2996% | 2.2106% |
| 1024 | 6 | 2.5969% | 2.5075% |
| 6144，原始逐行 A8 | 1 | 3.5616% | 3.4638% |

每个分组对原 BF16 H 动态计算 `max(abs)/127` 和最近偶数舍入，计算精确整数点积，乘对应分组的 AS 后按顺序 FP32 累加，最后乘全行共用的 WS 并做一次 BF16 舍入。此分析没有校准或使用评测题目。phase1/2 沿用旧合成工件的种子，是相关验证；需要新随机 GPU 实验才能检验可迁移性。

原始 K6144 对照的 42 层权重打包及缩放、每份工件的选中激活代码/缩放、完整 K 的整数点积和 BF16 输出均与旧 GPU 结果完全一致。504 个工件哈希、源码和模型文件前后哈希通过检查。未导入 Torch、Triton、vLLM、FlagGems，未使用 GPU，没有修改模型文件或结构。

单次整体 native `int_mm` 把所有 K 的整数结果先相加，不能直接表达每段各异的 AS。若采用此方向，需要在新的融合 Triton GEMM 中按组反量化累加，并实测额外 FP32 累加、缩放读取和寄存器占用的开销。不能从本表推断吞吐；本候选尚无 GPU 实现或模型评测，未采用。
