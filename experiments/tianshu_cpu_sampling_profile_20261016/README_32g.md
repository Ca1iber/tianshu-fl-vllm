# 天数vLLM CPU调用诊断

已在正式测试退出且GPU空闲后独立完成，本机全部原件核验通过，见[诊断报告](results/20261016/profile_32g/REPORT_32g.md)。原始官方argv与原3992.97版原生TopP/CV/KV16/S8；4K/256输出C64，先暖一组，第二组预暖32个纯Decode后采16个FULL/C64 frame。分别cProfile execute_model/sample_tokens，记录完整父调用、host wall/thread CPU和源码快照，无GPU事件。诊断有侵入性，不能当吞吐或GPU活跃时间；父子累计时间不相加。

同时只读记录16帧的logits、完整hidden states、sample hidden states与temperature/top_p/top_k的形状、stride、数据及storage指针，以及随机采样/penalty/logprobs等元数据。没有读取GPU张量值或额外同步。实际logits是BF16，logits/hidden/sampleHidden/temperature/top_p在这16帧各自地址相同，top_k=None；采样约束未启用。不把局部窗口地址稳定推广到全部请求。后续可单独验证采样Graph，尚无Graph收益结论。实际SamplingMetadata源码另入146份冻结快照。

另记录两类logits processor的具体类名及CPU标量、集合长度、Tensor元数据，避免把内置processor列表非空误当成存在活跃约束，或忽略min_p、min_tokens等状态。不会读取Tensor值。当前正式CLI使用lib/endpoint_request_func，未显式设置温度时采用模型generation_config中的temperature1/top_p.95；旧backend_request_func.py里temperature0的代码没有被当前CLI使用。该事实已通过实际源与B8..64纯TopP路由记录核对，小测试设置与正式一致。
