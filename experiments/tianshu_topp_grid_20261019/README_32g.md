# Top-P程序网格：只变并行行数

实际BI-V150的Top-P网格为16，B64由每个程序串行处理4行。保持当前GEO内核字节09156e66…不变，分别测试16/32/64个程序（限于实际batch行数），32K与16K两种tile分开比较。不是新的搜索算法或采样规则。

原生scratch仅按16程序分配，扩大网格时必须用足够大的独立scratch。候选按batch×vocab分配，模块级字典持有直到所有Graph结束；单一顺序流复用，不依赖临时Router对象保活。TopK保持原生网格/原生8K kernel。96项真实Router的CPU fixture验证网格、边界、缓冲容量与回退；这不代替GPU数值或并发验证。

GPU微测10场景，原始和改变输入的同一Graph，除严格CPU语义外额外要求相同tile候选与GEO控制逐位相同。7次轮转事件，各10遍重放；不测RNG、不测模型服务，不冒充正式成绩。只有通过后再决定API生命周期与实际服务是否值得测。
