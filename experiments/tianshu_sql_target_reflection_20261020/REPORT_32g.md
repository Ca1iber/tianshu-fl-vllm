# SQL目标表反射：天数CPU验证

参考沐曦8eb57f17d5a3a93f7399af440d8dc319b0916c00，只在独立实验中加载目标方法AST，未改天数实际FlagGems源码/活跃DB，也未启动GPU或模型。真实Triton3.6库一致性快照：1158表、43784行配置，全部列结构、主键、配置值与原实现一致，并经独立sqlite3逐行哈希重算。

组合主键、BIGINT超过32位、BOOLEAN/NULL、连字符表名、无主键、缺失表、空库与不反射无关表等CPU回归均通过。原生整库metadata只反射一次，随后使用其真实registry比较每张表；候选每张表单独反射。第一目标表一次带SQL监控的配对：4570.829ms→12.485ms，SQL语句11582→13。明确只有一次原生配对，不宣称重复统计稳定性。候选另测三张代表表各7次，中位12.044/12.083/11.129ms。

首版冗余逐目标全库反射已明确停止并保留原始代码/日志；没有把未完成首版当作成功数据。v2独立核验通过。本结果仅为配置冷路径；尚未集成服务，不宣称吞吐或TTFT变化。原始SQLite快照仅在容器，Git存代码、关键JSON和报告。
