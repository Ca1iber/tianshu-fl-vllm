# 天数 BI-V150 32g：Decode KV32两阶段一致与L0诊断

复查旧KV32启动微测发现：仅生产attention部分使用TILE32，reduce_segments仍使用原TILE16。新探针将生产和合并两阶段的TILE同步，保留原网格、64位整数和物理指针；先复测8个长场景，再复测14个短边界。

只同步TILE仍有错误：长场景均通过，14个短边界的KV32/stage1及stage2却全部失败，最大绝对误差约0.13~1.98，尾部未越界。失败长度为1/7/13/15/16/17/31/32/33/63/64/65及B64含0-query的33/65场景。不能仅凭4K长场景通过将它接入服务，旧失败及此次失败均保留。

随后增加独立可选--zero-init，复用既有Native L0生成器：无sink时L初值1→0，有sink时保留1，生成源SHA4a1f8bdfdb5b9399702941a0e499e62b52f104737aba6012a9056ef36f5c4d4e。其他kernel body不改。这一次14短边界和8长边界均通过GPU FP32、选定CPU参考、native L0对照、output/scratch未用尾部检查及Graph捕获重放。实验显示零初始化修复了观察到的错误；未证明CoreX编译器产生该差异的底层机制。
