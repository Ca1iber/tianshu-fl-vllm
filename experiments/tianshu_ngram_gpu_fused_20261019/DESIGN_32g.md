# GPU ngram 的独立整数搜索候选（未安装）

原生 GPU proposer 已支持异步调度，正在运行独立服务筛选。本目录只准备下一项
组件候选，不更改正在运行的原生版本。

原生算法分别构造长度3、4、5的全部窗口、与后缀比较并取最早匹配。新候选对
每个窗口终点只匹配一次最后3个token，再向前扩展到4/5；用
`(5-match_length)*(capacity+1)+start` 的整数最小值选择最长、最早匹配，随后
读取同一个后继token。每个请求分8段，每段按真实GPU长度循环；两阶段归约，
没有原子操作。仍搜索完整真实上下文，不截短target或draft历史。

输入token值不缩窄。仅匹配分数与元素地址偏移使用int32：B<=256、capacity
<=131072下最大元素地址33554431，分数哨兵393219，均有明确上界。输出draft
dtype保持输入token dtype，有效draft计数保持原生int64；不新增随机数、
不改变标准拒绝采样。短序列、disabled和后继token=-1的行为需要逐项一致。

CPU检查仅验证独立整数选择公式。之后必须在GPU比较实际原生实现与CPU参考，
覆盖无匹配、长度优先、最早匹配、重叠、短序列、异质长度、mask、strided、
131072上界及改变输入后的Graph重放，检查输入/尾部哨兵与RNG，之后才测组件
事件和服务。当前代码尚未导入GPU、编译、运行或接入模型，不能称为优化成果。
