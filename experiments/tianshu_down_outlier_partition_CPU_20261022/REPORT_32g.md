# Down 通道分拆的 CPU 数值检查，2026-10-22

本轮完成 42 层真实 Down 权重、504 份已有合成输入/输出工件的检查。把每层 6144 个输入通道按校准样本的最大绝对激活值排序，最大的 128 个通道保留 BF16，其余通道做逐行 A8W8，相关验证样本的聚合相对 L2 误差从 3.4638% 降至 2.5630%，相对降低 26.00%。这是进一步开展独立随机 GPU 实验的依据，尚无模型正确率或 GPU 性能结论。

| BF16 通道数 | 校准相对 L2 | 相关验证相对 L2 | 42 层额外 BF16 侧路权重 |
| --- | ---: | ---: | ---: |
| 0 | 3.5616% | 3.4638% | 0 MiB |
| 32 | 2.6333% | 2.8280% | 5.25 MiB |
| 64 | 2.3966% | 2.7043% | 10.50 MiB |
| 128 | 2.1162% | 2.5630% | 21.00 MiB |

按预先规定的“相关验证误差不超过基线 75%”门槛，最小全局候选为 128 通道，占 6144 通道的 2.0833%。不同层排序各自独立，通道数量全局固定；没有按答案或 M 临时挑选。原始 BF16 权重和模型文件没有更改，没有训练或改变模型结构。

校准只使用原 42-bank holdout 的 phase 0 合成隐藏状态，共每层 32 行，其中 4 行为零；phase 1/2 仅作相关验证，沿用原生成种子，因此不能称为独立随机验证。侧路用 FP64 点积后舍入到 FP32 近似理想累加，真实 GPU 归约的末位可能不同。误差对照是已保存的原始 GPU BF16 输出，每份取 8 行、32 列。

全部 504 个输入工件哈希通过检查，42 层 K0 的 INT8 权重和缩放哈希与原实验完全一致；模型文件前后 SHA256 均为 `14fb8e7f0a18d53d1f239773758bf581cee7e456a4523a54622c3a245b64402c`。程序未导入 Torch、Triton、vLLM 或 FlagGems，没有使用 GPU。当前正在运行的冻结版模型评测不受此次 CPU 分析影响。

复现：`CUDA_VISIBLE_DEVICES='' OMP_NUM_THREADS=4 OPENBLAS_NUM_THREADS=4 python3 experiments/tianshu_down_outlier_partition_CPU_20261022/analyze_cpu.py`。输出目录必须不存在；该程序有意拒绝覆盖原始结果。原始数组和通道排序仅存容器 `/workspace/benchmark-results/20261022_down_outlier_partition_CPU_tianshu`。Git 保留代码、计划、关键 CSV 和 CPU gate。下一步需要新种子的 GPU 数值/时间检查，再决定是否值得做新的 Math-500；本候选未采用。
