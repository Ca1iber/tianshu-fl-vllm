# 固定128 BF16通道侧路：首版GPU负结果

本实现的 GPU 数值检查和独立 CPU 检查全部通过，但速度门槛未通过，不进入 Math-500 或正式模型 benchmark，不采用。此结论只对应当前 BM16/BN64/BK128、warps4 的融合侧路实现和固定128通道，不代表其他 tiling 或侧路方案都无效。

42 层真实权重、全新独立随机输入、M64/512/4096 各两阶段，整段 MLP 42-bank 图每层中位耗时如下。七轮全保留，每轮三次图重放；每个 bank 使用对应层真实 GateUp 产生的 H。

| M | 原BF16 Down的整段MLP ms | 普通native INT8的整段MLP ms | BF16侧路128的整段MLP ms |
| --- | ---: | ---: | ---: |
| 64 | 0.134484 | 0.124581 | 0.142750 |
| 512 | 0.380857 | 0.335637 | 0.464925 |
| 4096 | 2.565138 | 2.128494 | 4.298262 |

M64 侧路吞吐比 BF16 控制约低5.79%，M4096 比普通 native INT8 约低50.48%，因此当前实现不值得进入耗时的模型质量测试。Down-only 辅助图共用最后一层 H，其测量范围与逐层真实 H 的 wholeMLP 不同，完整分项在 KEY_TIMINGS CSV 中如实标出。没有把组件结果称作完整模型吞吐。

所有全输出加权的独立 GPU 输入误差：普通 INT8 相对 BF16 为3.5309%，侧路128为3.0924%，误差相对下降12.42%。此前 CPU 相关工件使用选中行/列、不同M组合及统计权重，不能把两种范围的误差改善百分比直接横比。当前固定通道校准没有消除主要近似误差，也没有实际模型正确率结论。

完整 native INT32 与独立 NT Triton 参考一致，侧路输出通过预先规定的 BF16 舍入/FP32 累加界；全部42层252份工件的64512个选中位置又用完整K=6144的CPU INT64点积和FP64侧路重核。原BF16并非比特一致目标，明确不声称与原BF16输出完全相同。全部图经 NaN/哨兵污染后与 eager 输出哈希一致，输入/RNG/边界和所有权重、模型、源快照哈希通过检查。原24点 GateUp 完整二进制哈希守卫保留并通过。

本实验没有改任何冻结 GPU/数值源码。原始数组、全部轮次和快照保留容器 `/workspace/benchmark-results/20261022_down_outlier128_GPU_tianshu`，Git 保留源码、计划、关键 CSV 和独立 gate。已发布5911.45的Down prefill版本不受本负结果影响。后续先验证动态K分组缩放和W8A16方向。
