# 天数：融合 Philox 随机数生成与指数竞争采样（准备）

已有固定噪声采样融合只得到约0.33%的服务收益；本次新假设是进一步去掉词表大小 FP32 噪声张量的写回/读取。保持 TopP、模型精度与所有调度默认值。尚无新微测、服务、Math 或正式成绩，不采用。

新核将 Philox4x32-10、正指数噪声和 argmax(logits-log(q)) 融合；全局随机序列与旧 Torch/FlagGems exponential_ 不同，不声称逐 token 等同。使用64位计数器并明确保留高位进位，按全部padding计数器范围推进全局状态，避免相邻调用复用counter。独立请求generator、FP64 gumbel、非目标shape或CUDA Graph捕获必须退回原采样路径；服务适配器尚未实现。

独立probe先用CPU Random123整数参考检查12组随机整数及跨2^32/2^48偏移，再对模型词表及ragged词表的7种分布、3种分块核对完整CPU与同噪声生产采样；之后检查状态推进/重置复现、capture guard、固定counter的图内数值及分类频率。eager计时包含真实RNG状态处理、临时张量分配与同步，不把固定counter图的速度当真实服务收益。所有FP64参考只在CPU建立。

GPU微测必须串行；CPU/源码检查后先微测，数值或RNG契约失败则停止，不靠放宽断言认定成功。有清晰局部收益后才接入原始命令4K的小规模新鲜对照，输入种子每轮不同；新质量和正式4K按既有门槛另做。

第一版真实探针已停于单NaN边界，12组整数参考全过、前15个有效/全mask数值检查全过，第16项NaN与生产不符，无性能结果，不采用。独立诊断发现模型词表宽度下生产FlagGems的split softmax只在NaN位置输出NaN、argmax忽略它；CPU普通softmax整行NaN，因此两者参考契约不同。小词表16还有另一种全NaN argmax行为，不是服务适配目标。第二版独立文件保留第一版源码，按实际模型宽度NaN契约屏蔽单NaN，+inf仍返回0；CPU参考明确按有限logits归一化，完整保留CPU与生产同噪声双参考相等的断言，没有放宽数值误差或撤掉失败断言。第二版尚未运行。
