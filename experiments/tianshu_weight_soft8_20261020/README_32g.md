# 按输出行的软件8位权重：仅CPU准备，不采用

探索把实际BF16权重派生为uint8，以减小M64 GEMM权重读取量。每个输出行选取一个可覆盖最大绝对值的指数起点；三位fraction、符号位，低码冲零、高码限幅。不是原生硬件FP8，不改checkpoint、已采用KV格式或服务配置。8位编码会改变数值，不能借用原模型Math成绩。

CPU门槛已通过11个起点×65536种BF16位模式，共720896项，独立按实数指数/尾数舍入参考逐项相等；另验证全部2816个解码码点的再编码。CPU_GATE_32g.json 冻结三份源。这里只完成格式契约，kernel.py 尚未在GPU编译或运行，也未做真实GEMM性能、模型接入或Math。

计划GPU阶段先验证全部码值，再用真实权重将GEMM对照解码权重的完整FP32/CPU参考，同时单独报告相对原BF16权重的近似误差。只有组件和服务确有收益、全新Math严格>95%后才可能采用。当前正式16K正在独占GPU，本目录没有并行GPU任务。
