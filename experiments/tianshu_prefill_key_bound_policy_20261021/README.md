# Prefill-only bound hook: CPU prepared, not installed in a model

policy.install wraps the actual native hybrid.route_from_common once and returns its identical Route object, preserving native GPU cu handling. Candidate attaches the CPU-only helper's validated full-key bound; control does not compute an unused bound, so future paired timing must include the candidate's real metadata overhead. At exactly the selected dense prefill instance, only a valid matching mixed/pure prefill bound causes a copied staging kwargs with lower max_seqlen_k. The original dispatch kwargs remain identical for decode; other dense instances and missing/inconsistent metadata retain original behavior. Prefix key length is not replaced by query length.

No file writes are added in hooks. Extra shape fields extend existing dense.records, which the existing pipeline observer saves on shape changes/4096dispatches; saved counts are lower-bound Python observations, never model CUDA Graph replays. CPU source SHA in CPU_GATE binds policy/helper and the actual native Route AST. Twelve cases across both modes check original-return identity, real cu subtraction logic, prefix/mixed/63decode cases, pure decode/missing/invalid metadata, mismatched stage kwargs, other-instance passthrough and unchanged original q/out/k/v/table/length objects. No GPU initialization.

Not a standalone enabled optimization. Before a future Worker hook calls install, it must verify the supported MiniCPM/Iluvatar/BF16/single-device/non-spec/non-LoRA config, actual hybrid/pipeline installation, source closures and the separate successful full-active-cell GPU component gate. A new independent model profile/controller must compare against the qualified baseline, prove actual paths and retain arena8192 for this bound-only factor. Current formal8192 and staticcompile420 source closures are untouched; this code is not part of their Math/results. A capacity change is a separate experiment.
