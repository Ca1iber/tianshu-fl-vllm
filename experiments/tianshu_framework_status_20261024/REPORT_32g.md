# 天数框架层已验证进展（截至2026-10-24）

已找到并采用可复现的框架优化，主要是调度预算和未来 KV 准入；近期量化/算子的收益另列，不能都归因框架。下列百分比来自不同日期和父版本，不能相加，也不意味着当前 r4 的全部收益由这些开关产生。

|框架改动|机制|实测与采用依据|
|---|---|---|
|默认调度 token budget 2048→4096|在原 serve argv 不变、用户未显式指定时选择4096；显式参数优先|当时 N64 配对 +3.2677%，新 Math102/105；完整4K N256 4997.05→5101.45，+2.0892%，热3轮极差/均值0.1468%|
|未来输出 KV 准入|prompt+max_tokens 计算虚拟KV需求，推迟过早准入，保留原生运行中分配和前缀缓存|独立16K N64配对3737.45→3887.60，+4.0174%，抢占6→0；最终含128MiB arena/maxseq64的组合完整16K3723.12→3885.91，+4.3724%，新Math103/105；组合4K基本持平|
|prefill arena 512→128MiB|收缩复用BF16暂存，释放空间给KV|独立4K配对5031.30→5030.59，-0.0140%视为持平；实际KV容量增加12480token。不将容量增加当吞吐收益|
|Graph批次覆盖与启动预热|沿用用户提出的稀有M补齐思路，扩大捕获/预热覆盖，减少请求期首次调优|4096版本实际83预热点，属于稳定性/启动准备工作；没有把它单独记成某个吞吐提升百分比，亦不声称全部冷点都消失|

8192预算完成独立Math和正式4K，但较当时4096版本仅+0.396%，TTFT约+16.55%，不是同次配对且吞吐差小于轮间波动，未替换推荐版。不能据“预算越大越好”继续盲增。

未采用的框架方向：纯decode元数据融合（微测2.023→0.321ms，服务仅+0.0805%）、页表增量同步（原H2D成本约0.091ms）、KV NHD/HND排列（基本持平）、prefill cadence（N128约+0.647%，更强版本TTFT明显退步）、请求位置融合（服务-0.1409%）。投机框架也做过，但已测ngram服务明显低于非投机，尚无可采用端到端收益。微测与组件改善不能替代正式服务成绩。

KV采用分页分配和前缀复用；未来输出准入是在原生分配器前增加需求约束，并非改模型为MLA。当前K软件8位/V BF16格式属于运行时缓存格式优化，不能与MLA模型结构变化等同。近期W4、W8线性层等属于量化与算子路径；当前正式r4 6050.94 total tok/s不作为框架独立贡献。

筛选方法也需防止缓存干扰：24日O64原脚本N64缩量对照，两组累计前缀命中均74.707%，且都未过热3轮<1%波动门槛，不用于正常4K提速结论。后续另建跨轮新seed、两组对应seed一致的N128协议，每轮检查实际命中≤1%、零抢占；此项是评测修正，不记为架构加速。
