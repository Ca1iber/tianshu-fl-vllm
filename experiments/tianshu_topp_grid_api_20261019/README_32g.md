# 16K tile / grid2：真实接口与服务准备

当前32K GEO/16程序控制保持。候选仅32≤B≤64、130560词表、纯Top-P、连续FP32词表维时，使用同一GEO算术源码、16K tile、min(B,2×原网格)程序；其余调用转发完整原路由。不改Sampler函数、import aliases、温度、p、RNG或官方serve argv。

来自网格组件试验的B64 BF16 normal为2.471295→1.782313ms，BF16 peaked为1.897018→1.209859ms。组件输出相同tile逐位、CPU严格1e-6通过；尚不是模型服务成绩。

接口版scratch与组件版唯一的存储策略差异：32..64行共享一个64×130560的持久缓冲，约32MiB，避免给每个动态B累积一块缓冲。顺序worker流使用，不能声称任意并发流安全；原生缓存同样遵循顺序调用。组件版原文件不修改，新kernel_route.py独立保存接口存储策略，CPU门槛检查新源hash。GPU接口必须再检查批次切换、改变输入的同一Graph、实际Sampler默认/混合/逐请求RNG和边界回退。

接口检查计划13组分布/批次×6个p×2阶段=156掩码、21次真实RNG、8边界回退；之后通过独立下载核验才生成GPU_GATE_32g.json。服务仍是原serve命令，双方仅候选开关不同，4K/1K C64 N64各3轮、首轮排除、每轮不同输入种子，逐轮报告。没有接口实测前不能启动服务，没有新质量与正式测试前不能采用或更新4093.81最佳。
