# K4 v2：精确BF16位构造消除了主要转换开销，整体仍负收益

保持K4量化、页面与scale不变，仅将[-8,7]小整数数值cast改成精确BF16位构造。实际生成helper在连续/跨步、两阶段同Graph下，覆盖全部256个packed byte（含保留code0=-8），34816个BF16输出逐bit一致。全部8场景、两组两阶段的2768896个attention输出经GPU FP32和独立CPU FP64复核，6454798336字节raw缓存按原始输入独立重建，哈希全部一致。未改变v1的负收益记录。

所有9次交替20回放的原始时间保留，均取中位数。相对v1，C64 4096的K4耗时从2.82259降到0.77072 ms；对应对照分别0.55770和0.55779 ms。新实际binary的TTGIR local_alloc从3个变成2个，K的额外4KiB共享内存消失；LLIR int16->bfloat sitofp从32处变成0处。C64 K4共享内存8192B、180寄存器、0spill，与当前K8 8192B/176/0相比仍有额外读取/解包/缩放成本。

CPU独立复核与全部raw/binary来源见BITCAST_GPU_GATE_32g.json，逐场景关键时间见BITCAST_KEY_RUNS_32g.csv。位构造K4仍全部慢约35%–46%，不满足收益门槛，不接模型、不跑Math。下一独立word-load变体只测16-bit一次读四个nibble，减少load/展开成本；与本次独立记录，不回写本次失败。10496B只是组件页实测和原生Spec计数，实际模型allocator未接入。

完整fixture输出、数值参考、两阶段输入哈希、源快照、二进制与IR、全部计时和独立FP64日志在容器持久盘归档，SHA见BITCAST_RAW_ARCHIVE_32g.sha256。原始CPU/GPU脚本和前版记录保持可复核。
