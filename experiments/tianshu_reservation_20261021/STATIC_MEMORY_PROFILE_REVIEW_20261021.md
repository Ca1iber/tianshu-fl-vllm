# Staticcompile内存观察：原因尚未证实

当前static420对照实际KV40731，候选40143，减少588blocks。原engine.availability对照KVbytes21021191884、候选20718083276，差303108608bytes=289.066895MiB。两臂回调时torch_memory_allocated均6691412480，arena均8192pages，scratch134234112B+table32768B，reserve前6448255488/后6582522368相同。故不能把差异直接解释为额外packed权重、较大arena或更多此时仍存活的torch张量。

WorkerFL.determine_available_memory在memory_profiling_fl中运行profile_run并读取allocated_bytes.all.peak，随后profile_cudagraph_memory，再通过native non_torch、activation peak、weights及默认开启的Graph估计计算KVbytes。source显式使用原profile_torch_peak分离Graph池；不能误报成Graph双计费bug。首次Inductor调优临时峰值、non-torch持久代码/allocator、真实Graph估计差异均可能，现有日志不足归因。

若后续研究，应先记录native三项和实际return。KVbound-only模型profile目前仍CPU准备，在Worker原方法返回后只增加startup metadata记录，不改return/config，不增加warmrun，不resetpeak。它不复测static的因果，仅提供新两臂相同profile的原生预算观测。

潜在单独研究：在原KV预算保持不变的观察实验，原determine返回后、KV分配前保留RNG状态额外测同一dummy的warm激活峰值，披露持续分配和原native预算；不能直接把startup峰值删掉并假定安全。若未来调整peak，必须保持weights、retainedworkspace、arena、non-torch和Graph池完整计费、实测worstcase，无任意手填KV大小或提高0.85。没有实施此warm观察或预算变更。
