# O64 minmax 新输入 N128：稳定 +0.704%，不升级完整 benchmark

修复原脚本缩到N64重复seed导致热前缀复用的负载缺陷后，使用独立预注册协议：4K/1K C64 N128，两个独立服务各4轮、预先排除首轮；每轮seed不同，配对对应轮seed相同。原benchmark SHA和原13参数serve不改，解析/汇总直接复用原脚本CPU函数，未把新协议称作正式N256。

配对均值吞吐 +0.70426%，TTFT +0.74370%。双方均稳定，但未达到预先规定的≥1%推进门槛，因此不为此单项运行原脚本完整N256，也不替换当前r4正式6050.94。这里的1%是实验推进选择，非官方正确率规则；O64 minmax的新鲜C8/C64 Math均102/105，质量已过>95%。

1024/1024性能请求成功，8轮每轮查询524288 token、命中0、抢占0；实际客户端seed=2026102401..04，双方对应配置一致。原脚本不序列化完整输入正文，本协议也未保存正文，不声称重算了请求内容哈希。逐轮before/after计数器、客户端日志、配置和独立JSON均留容器。

模型来源同959份、实际环境65项、原serve argv13项，唯一归一化差异为O64_MODE；双方同装载93585408字节额外派生缓冲，原BF16/W8保留。控制/候选真实KV块数36479/36488，差144token，两者均足够64×(4096+1024)，不能说物理容量完全相同。真实FULL64重放7718/7719次，全部原GU融合、Down/LM、prefill native attention、K8/VBF16、前缀缓存与未来KV准入审计通过。全部105题质量数据和双方来源绑定在GPU闲置后重新独立核验。

原先重复输入N64的表面+4.01%不能外推；此处新输入稳定小幅正收益才是本项可用结论。QKV/O各自组件省时不等于整条模型的吞吐增益，接下来独立验证拟合QKV+O组合；不得借用本minmax模型的质量分。
