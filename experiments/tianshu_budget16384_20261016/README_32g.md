# 天数调度预算16384的候选准备

本方向仍使用4K输入/1K输出工作负载；16384仅指每步调度token预算，不是16K输入benchmark。

假设：扩大Prefill批次可减少调度步数并改善大M GEMM效率。此前4096到8192只约+0.61%，本方向仍需实际服务验证，不能假定更大必然更快。预热从当前4096预算的83点扩到16384预算的131点；保留原75点并按256补足，避免新预算引入现场GEMM autotune。所有模型、并行、量化、投机解码和图模式守卫保持。

初始CPU准备：对比8192扩展，执行真实configure/warmup和桶向上取整，确认8192以内映射完全相同及非法模型回退。尚无GPU服务、显存容量、预抢占、质量或吞吐数据，不采用。实际运行前必须组合当前CV/KV16/S8/原生TopP配置，保持4K/C64/N64，核验实际worker预算、131预热点、KV容量和零preemption；单独新目录运行新鲜对照。采样融合当前服务仍独占GPU，本准备不启动GPU。

实测已完成：稳态+0.872020%，TTFT约+3.26%，不单独采用。完整报告见 `results/20261016/service_32g/REPORT_32g.md`。
